Input decision

Which input should start an image-to-video job?

The short answer

Start with a still image only when it already shows the scene you need to protect. Start with ordered frames when the viewer must see separate beats. If you only have a voice, a moving clip, or a text idea, name that input honestly before you write a motion prompt: it describes a different production job, not missing detail inside one photo.

This is a planning and review method. It does not claim that every video service accepts every input type.

Sort evidence before you ask for motion

“Image to video” is specific only when a visible source scene is present. A source photo can establish the subject, framing, lighting, and the nearby details you intend to inspect after generation. A voice, a prior clip, or an idea can still be useful, but each leaves a different part of the visible scene undecided.

An archived 2021 TokkingHeads product page routed text, voice, video, and a single portrait into different avatar-animation inputs. This page does not reproduce its wording or promise the same options today. The useful planning constraint is simpler: the starting evidence changes the job before a prompt is written.

One still sceneUse it when the clip may begin and remain inside one recognizable composition. Protect its subject, crop, light, and key detail while allowing one small motion.
Ordered still framesUse them when a later beat needs a different angle, location, or product state. The sequence provides a new composition instead of asking one photo to invent it.
Voice or spoken lineIt gives you timing or performance intent, not proof of a source scene. Before visual generation, decide what picture carries that speech and which visible detail must be checked.
Existing moving clip or text ideaA clip gives temporal reference; text gives desired action. Neither automatically supplies a still source anchor. State what visual evidence is missing rather than hiding it in a longer prompt.

Keep a source fact separate from an instruction

A source fact can be checked: “the cup begins on the table, label facing front.” An instruction expresses an allowed event: “the hand lifts the cup once.” Mixing them leads to vague reviews because the final frame has nothing stable to compare with. Write one line for each before you generate.

Two-line input briefSource fact: One front-facing product photo; label, table edge, and window reflection are visible.
Allowed event: A hand lifts the product once while the camera stays fixed. The label remains readable until the object leaves the frame.

Use a four-question input check

  1. What is already visible? Name the photo, ordered frames, voice, clip, or text note without calling them interchangeable.
  2. What must stay comparable? Pick one protected visual reference: a face, label, edge, lighting cue, or position.
  3. What may change in this short test? Give one owner the motion job: subject, camera, light, or environment.
  4. What frame proves the job is done? State the visible final condition before you press generate. If no evidence could prove it, narrow the brief or prepare another source frame.

Questions people ask

Can a voice note be an image-to-video input?It can be part of a workflow only if the tool and project support it. For planning, treat it as performance information; choose the visible source separately.
Can one photo cover a new angle?Not as evidence. If the new angle is indispensable to the viewer, prepare a second source frame instead of expecting a prompt to document unseen detail.
Why not begin with a long prompt?More description does not create a comparable source reference. First decide what is visible and what is allowed to move, then keep the test small enough to review.
Where should I go next?Use one photo versus a storyboard when choosing between source-frame workflows, then use the render review sheet to judge the result.
