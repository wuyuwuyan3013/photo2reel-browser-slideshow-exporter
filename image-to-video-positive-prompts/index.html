PROMPT CHECK
Before the next render

Write the scene you want—
not the failure you fear.

A negative instruction leaves a model to infer the desired alternative. For image to video, replace it with a stable starting state, one allowed motion, and a check you can see in the rendered clip.

The short answer

Turn “don’t let it change” into an instruction that names what stays stable and what may move. Then judge that single condition in the result before adding another constraint.

Why a negative prompt is hard to review

“No flicker,” “do not change the product,” and “don’t move the camera” each name a risk, but not the image state that should replace it. A result can obey part of the prohibition while still missing the shot. A reviewable instruction tells you what should be stable, what is allowed to change, and where to look for evidence.

Hold

Name the stable part

Point to the face, label, horizon, or composition that must remain recognisable. Use ordinary visual language, not a broad promise of consistency.

Move

Allow one action

Give the subject, environment, or camera one visible job. Start with a small movement before asking for a sequence of events.

Check

Choose one proof

Decide what you will inspect in the final seconds: identity, label legibility, a steady horizon, or the intended camera path.

Rewrite the risk without pretending a prompt guarantees it

Risk you noticeVague negative promptReviewable replacement
A face shifts during a head movement“Do not change the face.”“The person keeps the same facial features while making a slow head turn; locked camera.”
A product label becomes hard to read“No distorted text.”“The package front stays facing the viewer while soft light moves across the surface; keep the label readable at the end.”
The setting drifts behind a still subject“Don’t change the background.”“The room layout and horizon remain fixed; only curtain fabric moves gently in a light breeze.”

Important limit: a better instruction is a clearer test, not a guarantee that every model or render will preserve the requested feature. If the condition fails, simplify the allowed movement before adding more wording.

Use this compact prompt worksheet

  1. Write the risk in plain words. Keep it out of the final prompt for a moment. It is useful as a diagnosis, not yet as a direction.
  2. Name the desired stable state. Describe the part of the starting frame a viewer should still recognise.
  3. Permit the smallest needed movement. Choose one action for a subject, environment, or camera.
  4. Write one final-frame check. If you cannot state what you will inspect, the constraint is too abstract to evaluate.

Questions about positive image-to-video prompts

Does “locked camera” mean nothing can move?

No. It assigns the stillness to the camera. A subject or an environmental detail may still move if you describe that motion separately.

Should I describe every part of the image again?

Not by default. For image-to-video, the source image already carries much of the composition and appearance. Start with the motion and add visual detail only when the change itself needs it.

What if the output still changes the wrong thing?

Reduce the allowed movement, make the stable feature more concrete, and rerun one change at a time. Treat the result as feedback, not as evidence that an added phrase universally works.

Are negative prompts unsupported everywhere?

No universal rule applies across tools. This page uses the Runway guidance cited below as a documented example of why a positive, explicit direction is the safer starting point for that workflow.
